# UX and Design Rationale

## 1. Clear navigation and reduced friction
The navigation is simple and consistent across pages so users always know where they are. A clear booking call-to-action is placed in the main nav to make the next step obvious without asking the user to hunt for it.

## 2. Real-time booking summary
The booking summary updates as users choose their service, time, and date. This reduces uncertainty because people can see costs and details before they submit, which helps them feel more confident and reduces avoidable mistakes.

## 3. Simple login and registration flow
The site uses a local browser storage approach for a demo environment. This keeps the process quick and easy for testing while still matching the expected flow of a real booking system.

## 4. Accessible structure
Buttons, labels, and form inputs are kept clear and readable. This is important because good UX is not only about visual style; it also means users can understand and operate the site without confusion.

## 5. Mobile-first browsing support
The menu collapses cleanly for smaller screens, which improves usability on phones. This is important because many users will visit the site on mobile before booking in person.

## 6. Why this matters for portfolio quality
These choices show intentional thinking, not just decoration. A strong portfolio project demonstrates that design decisions were made to support usability, trust, and task completion rather than just visual style.
